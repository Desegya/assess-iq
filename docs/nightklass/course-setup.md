# Course setup and management

The course library reads the full server list with `cache: no-store`. It reloads when the route changes, the browser tab regains focus, or a suspended page is restored. Responses from older requests cannot overwrite a newer list or reinsert a deleted course. Both Dashboard and My Courses use the same hook.

My Courses sorts by course code, ignoring case and sorting numbers naturally. Courses without codes appear afterward, sorted by title. Search matches course codes and titles without changing the saved course list; code searches accept omitted spaces such as `BIO101` for `BIO 101`. Search results show a count and a clear-search action. The combined planner still offers all courses when the visible library is filtered.

Study screens offer an optional **Enter focus mode** control: Today, lessons, topic quizzes, flashcards, exam practice and mocks. It hides the app sidebar, header and mobile navigation and requests browser fullscreen with navigation UI hidden. Fullscreen requires the learner's button click; browser rejection or missing support keeps the app's focused view available with a short explanation. A sticky **Exit focus mode** control stays visible, and Escape or leaving browser fullscreen restores the normal view. Focus continues between study routes, ends when navigating to another part of the app, and is not automatically restored after reloading.

Lesson focus keeps lesson content, the contents list, source references and the quiz action, while hiding version selection, regeneration/report panels and external resources. Existing child screens stay mounted, preserving feedback drafts and quiz choices. Current-day task actions stay available in Today; earlier unfinished-work extras are hidden until focus mode is left. Browser and operating-system controls remain subject to the browser's fullscreen rules; the app does not permanently change Chrome settings. Focus-mode checks cover native desktop fullscreen, blocked/unsupported fallback, Escape/exit behaviour, route changes and state preservation on desktop and mobile.

Generated lessons explain concepts directly rather than repeatedly narrating what “the notes” or “the excerpts” say or omit. Combined mode builds a comprehensive, integrated explanation: approved excerpts anchor the course scope and terminology, while accurate background knowledge supplies prerequisites, mechanisms, comparisons, applications and examples. Inline citations stay attached only to claims supported by their excerpts. Conceptual topics receive worked scenarios as well as definitions; sections address reasoning, limitations and common mistakes. Material-only mode remains restricted to its excerpts and quietly omits unsupported additions. These writing changes take effect when generating or regenerating a lesson; saved versions are not rewritten.

Every course card exposes Edit course and Delete course. A course page also has a selector for switching between saved courses. Switching remounts that course workspace so draft topics, errors and planning state cannot carry over from another course. Delete asks for confirmation. Courses linked to an exam goal must first be removed through that goal's Edit subjects flow.

Adding a manual course, uploading an outline, accepting programme suggestions, and selecting WAEC/JAMB subjects were inspected. None intentionally replaces the learner's complete course list. A failed batch of programme additions now deselects already-saved courses so retrying adds only the remaining choices. The original report of a missing course was not reproduced as a database overwrite; list freshness and the regression checks address the observed risk without claiming a proven cause.

## Guided setup

The course chooser opens a short, collapsible three-step guide. The example button fills the form without creating any records. The learner can edit it, enter an optional exam date, and see what happens after Create course. Help disclosures work with touch and keyboard input. A full Quick guide is linked from the sidebar and course guides.

The optional target exam date is saved on the course. It preselects the exam-date option in Study setup; without a date, the semester plan remains available. Editing the course can change or clear this suggestion. Existing plans keep their own date and must be rescheduled on the plan page. Dates must be future calendar dates in Africa/Lagos; unrelated edits can retain an unchanged historical target date.

## Deployment and checks

**My Courses → Suggest a study plan** builds a combined timetable for selected courses. Learners choose days-only or timed sessions, total weekly hours, study days, maximum courses per day, daily effort limit, plan length, and optional per-course difficulty ratings. A preview shows approximate weekly allocation, explanations, the first seven study days, and capacity warnings. Editing a preference invalidates the preview. Applying recomputes against current progress and commitments, then replaces the selected courses' future plans together in one transaction. Other courses remain reserved; today's tasks move to the replacement plans with their task IDs and completion state intact.

Allocation uses course credit units (three, explicitly labelled as assumed, when absent), difficulty estimated from topic workload or rated by the learner, measured quiz mastery, and low confidence from completed study. It distributes bounded study blocks jointly, obeys each day's course/effort limits, leaves breaks in timed mode, and gives more attention to harder or weaker courses. It uses shorter blocks when many courses share a small budget. Courses without an outline receive clearly labelled course-study tasks linking back to the course; an outline is needed for specific lessons. No quiz evidence is presented as measured mastery until graded results exist.

Automatic adjustment is enabled by default and can be turned off when applying a suggestion. Graded quizzes and completed study tasks trigger a joint update of future unstarted work. Today also reviews a saved timetable once on a new local calendar day, accounting for unfinished work. Updates keep selected preferences, weekly budget, daily limits, current-day commitments, in-progress work and completed history. Adjustment reasons are saved in each course plan's history and shown in the combined planner. Capacity shortages during adaptation are logged rather than resolved by overloading a day. Failures to adjust do not discard a successfully saved completion or quiz result.

The course workspace keeps learning actions near the top. Outline, uploaded materials, and study setup are collapsible and accessible from the section shortcuts; topic readiness is also expandable. Uploaded files remain listed with their status, upload date, and an authenticated open/download action.

Lecture notes support selecting multiple files at once, with a 20 MB limit per file. Files upload and match to topics sequentially; each gets its own progress and error. Upload or matching failures leave the other files intact. Retry topic matching reuses the saved document instead of uploading another copy. Rate-limited requests wait for the server's retry interval (up to 60 seconds) and retry once; ambiguous network/server upload failures require an explicit retry to avoid creating duplicates.

New course uploads also receive a relevance check against the course title, description and outline, using a sample of their extracted content. A clear match can be used normally. Suspected mismatches, insufficient readable content, and unavailable/uncertain checks stay saved as **Needs course review**, with a persistent explanation. Held files are excluded from material availability, passage retrieval, automatic outline expansion, topic matching, and question generation. The uploader or an administrator can explicitly confirm a readable file for that course; the uploaded-file list also supports removal. Batch results link directly to the file's review warning. Matching is an automatic aid and can make mistakes; it does not guarantee every wrong-course upload will be detected.

Existing documents retain their approved state; this change does not retroactively assess previously uploaded files. New uploads start pending and are not indexed for course study until approved. PowerPoint accepts `.pptx` and legacy `.ppt`, including browsers that send Office files with generic MIME types. The server validates signatures and the slide package, extracts actual slide text, and indexes it for lessons. Unreadable or image-only presentations fail with an actionable message rather than becoming empty “ready” materials. Rebuild the API container (it installs Debian `catdoc` for `catppt`), apply `20261104130000_legacy_powerpoint`, and regenerate Prisma before enabling `.ppt`. For a native development server, install a current patched `catdoc` package with `catppt` on PATH or set `CATPPT_PATH` to its executable. The legacy extractor uses a private temporary file, runs without a shell with a 15-second timeout, and deletes the file afterward.

PowerPoint unit checks exercise real `.pptx` extraction and malformed presentations. To also run the legacy smoke check, supply `PPT_TEST_FIXTURE` pointing to a known `.ppt` test file and `CATPPT_PATH` pointing to `catppt` when running `npm run test --workspace=@assessiq/api -- src/modules/documents/`. The smoke check was run with Apache POI's `test-data/slideshow/basic_test_ppt_file.ppt` and the same Debian-patched catdoc source used by the container package.

Study setup defaults to a per-course weekly budget. Learners can prefer weekday evenings and weekends, weekends only, or flexible daytime/evening study, and protect configurable weekday work/class hours with an hour on either side. Scheduling starts tomorrow in the learner's timezone. Blocks last up to 60 minutes with 15-minute gaps, end by 22:00, and are limited to two hours per course and three hours across courses per day. Other courses' active sessions are reserved. Impossible budgets are rejected before replacing the current plan. Short final weeks receive a proportional budget; regular practice fills the budget after initial lessons. Updating a budget plan keeps its saved preferences, weekly boundaries, and time already committed in the current week.

Exact-time scheduling remains available as an alternative. These windows are shared across courses using exact times; rebalancing excludes reservations belonging to weekly-budget plans. Plan writes use a per-student transaction lock when allocating sessions.

Learners with changing daily schedules can choose **Day-by-day timetable (no fixed times)** in Study setup. They choose study days and an approximate weekly workload; no free-time windows or work hours are required. Topics and revision are assigned to lighter days while considering the estimated effort already reserved by all other active courses. A daily timetable permits up to two courses and three hours total per day, and two hours per course. These are workload estimates, not clock appointments. The API defaults to three hours/week when a daily request omits its budget. Saved preferences and daily mode survive regeneration and adaptation.

Daily sessions store null start/end times. Today and the dashboard label them “Anytime today”; the course plan labels them “Anytime this day.” The dashboard links to Today, where explicit completion is saved and counted. Opening a lesson does not imply completion. Failed completion requests keep the task unfinished and show a focused inline error. Today lists unfinished earlier work separately, linking to its course plan for completion or an explicit plan update, rather than adding overdue work to the current day's workload. Today and overdue queries accept the learner's timezone so the calendar date stays correct around midnight.
